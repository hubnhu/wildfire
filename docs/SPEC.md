# 野火 Wildfire 网站：建站说明

适用于本项目的开发、内容编辑与验收。

## 0. 规格与内容来源

产品行为以本规格为准，文案由 `src/data/`、页面和组件维护，视觉见 `src/styles/global.css`。文案修改需负责人确认；未确认占位不补写。验证见 [PROJECT](PROJECT.md)，实现见 [ARCHITECTURE](ARCHITECTURE.md)。源码路径相对仓库根目录。

## 1. 这是什么

野火由白老师个人发起，连接有真实项目的发起人与想积攒经历的学生、转行者。网站介绍理念、展示项目、接收申请；主要服务从小红书进入的大陆手机访客。

## 2. 目标与非目标

目标：五类页面；项目和发起人由数据生成；申请和简历通过邮件处理；大陆手机能阅读及提交。

不做：注册登录、后台、自助项目入口、英文版、FAQ、首页数字统计条、人物照片和数据库。项目由负责人手动添加，全站简体中文。

## 3. 技术要求

### 3.1 技术栈

- 使用 Astro 生成静态文件，以同一 Cloudflare Worker 提供静态资源和申请接口。不要引入重型框架或客户端状态库。
- 页面要在不执行 JavaScript 的情况下也能读到全部内容。JavaScript 只用于：项目横向拖动、表单校验和提交、申请页预选项目。

### 3.2 中国大陆可访问性（重要）

- 静态资源及字体同域，仓库代码不得直接加载 Google 或其他站外资源，不得另增统计工具或不稳定的第三方验证码。
- 访问统计由负责人在 Cloudflare 和 Tag Manager 后台配置，经 Google tag gateway 走本站 `/wd7e`；脚本不入仓库，统计事件不含申请人填写的内容。实现见 [ARCHITECTURE](ARCHITECTURE.md#访问统计)。

### 3.3 字体

正文用系统无衬线字体，大标题用最粗可用的系统宋体；字体栈以 `src/styles/global.css` 为准。

### 3.4 性能与适配

- 手机优先。在 390 像素宽度下不得出现页面级的横向滚动。
- 首屏不依赖大图。全站目前唯一的图片是小红书二维码。
- 可点击区域高度不小于 44 像素。

### 3.5 占位符检查

检查脚本 `npm run check:content`：构建产物中包含“待定”或“待朋友”的方括号占位会阻止发布。不保留项目占位豁免。申请、成功提示及须知必须通过严格检查；开发构建和关闭申请的构建允许草稿，具体命令见 DEPLOY.md。

### 3.6 托管和邮件服务

托管及邮件实现、技术理由见 [ARCHITECTURE](ARCHITECTURE.md)，变量与密钥边界见 [CONTRIBUTING](../CONTRIBUTING.md#环境变量)。

## 4. 网站结构

| 路径 | 页面 | 实现入口 |
| --- | --- | --- |
| `/` | 首页 | `src/pages/index.astro` |
| `/projects/{slug}` | 已发布且有详情的项目 | `src/pages/projects/[slug].astro` |
| `/initiators/{slug}` | 项目发起人 | `src/pages/initiators/[slug].astro` |
| `/apply` | 申请表，支持 `?project={slug}` | `src/pages/apply.astro` |
| `/terms` | 当前参与须知 | `src/pages/terms.astro` |
| `/terms/archive/{version}` | 历史参与须知 | `src/pages/terms/archive/[version].astro` |

导航：

- 首页顶部导航：理念、有何不同、项目、如何参与、我是谁（都是页内锚点），加一个"申请加入"按钮。
- **所有页面的"申请加入"按钮都直接去 `/apply`**，不要先跳到页面底部。
- 其他页面的导航：首页、全部项目（首页的项目区）、申请加入。
- 页脚：左侧"野火 Wildfire"，右侧"参与须知"链接。没有别的内容。
- 手机上导航项较多，可以做成一行横向滑动或收进菜单按钮，但"申请加入"按钮要一直可见。

## 5. 内容数据

`src/lib/content.mjs` 是页面和 Worker 的共享入口，导出岗位表、id → 名称查找、项目及发起人、开放申请项目列表和站点发起人。具体内容仅在 JSON 维护。

### 5.1 岗位

`src/data/roles.json` 是全站唯一的有序岗位表，每项 `{ id, name }`；id 唯一，项目和申请只引用 id。岗位顺序：产品、设计、开发、数据、社交媒体运营。卡片“需要”、详情岗位名和表单选项统一查表。

### 5.2 项目

`src/data/projects.json` 字段：

| 字段 | 说明 |
| --- | --- |
| `slug`、`name`、`oneLiner` | 路径、名称及卡片/详情简介 |
| `status` | 想法、开发中、已上线、在营业务、筹备中 |
| `profitPotential` | 暂无、低、中、高、未知 |
| `roles` | 有序数组 `{ role: 岗位id, description?: 说明 }`；岗位须存在，有详情页时每项说明必填 |
| `rolesHeading` | 可选岗位区标题 |
| `collaboration` | 合作条件，自由文本 |
| `mode` | cocreate 共创；company 实习或招聘 |
| `initiator` | 发起人 slug；已发布项目必须引用存在的发起人 |
| `published` | 控制卡片、计数及发起人列表，不提供仓库保密 |
| `acceptingApplications` | 布尔申请开关；为 true 时必须 published |
| `hasDetailPage` | 是否生成详情；为 false 时不显示详情链接 |
| `about`、`progress` | 详情介绍与进展 |
| `externalUrl` | 可选；经负责人确认的体验链接，详情页新标签打开 |

首页“加入之后”的条目在 `src/data/collaboration.json`；项目详情不显示该区块。未获展示许可的资料不入库，测试用合成数据。

### 5.3 发起人及站点

`src/data/initiators.json`：slug、name、oneLiner、bio 段落数组、可选 xhsUrl/xhsId、links（`[{label, url}]`，label 非空，url 以 https:// 开头；简介后用 text-link 新标签页显示，无则省略）。首页与专页共用 bio，不混入私人记录。仅为至少有一个已发布项目的发起人生成页面；列表按 initiator 汇总，有详情的项目名可点击。

`src/data/site.json` 的 founder 引用存在的发起人，决定首页“我是谁”；其余站点配置及公共协作文案同样由数据维护。

## 6. 各页面说明

每页使用已维护的页面模板、组件和数据。本节规定区块顺序与交互行为，文案修改需单独确认。

### 6.1 首页

区块顺序：导航、开头、理念、有何不同、项目、如何参与、我是谁、申请、页脚。

- **有何不同：** 一张对比表，野火对普通实习、付费实习和背景提升、训练营和课程，四行。手机上表格在自己的容器里横向滚动，页面本身不滚动。
- **项目：** 卡片横排，支持触摸、鼠标拖动和箭头；拖动结束不误点链接。宽度 `min(350px, 82vw)`，露出下一张边。右上角“共 N 个，左右拖动查看”的 N 来自已发布项目。卡片显示名称、状态、简介、需要、盈利可能、合作条件、发起人链接；已上线标签强调色实底，其余描边；有详情才显示详情链接。
- **如何参与：** 三栏（你能得到什么、你要付出什么、成果归谁），下面一个描边框（部分项目以实习或招聘方式开启的说明），再下面"加入的三步"和"加入之后，是一份真实工作的样子"。
- **我是谁：** 左边是站点发起人的姓名、小红书二维码、一行说明、一个直接打开小红书主页的链接（新标签页打开）。右边是负责人提供的四段简介和一个通往其发起人页的按钮；简介与发起人专页共用。
- **申请：** 一段话加一个去 `/apply` 的按钮。

### 6.2 项目详情页

区块顺序：导航、返回链接、项目名和状态、一句话介绍、申请按钮、五项信息（状态、需要的岗位、盈利可能、合作条件、发起人）、这个项目是什么、现在到哪了、需要什么样的人、发起人条、申请、页脚。底部申请区只保留标题及按钮。

- 两处按钮统一“申请加入”。项目开放申请时去 `/apply?project={slug}`，否则去 `/apply`。
- `mode` 为 `company` 的项目，详情页在显眼处显示："这个项目以实习或招聘的方式开启，遵循项目方公司的规则。"

### 6.3 项目发起人页

区块顺序：导航、返回链接、"项目发起人"小标、姓名、一句话介绍、简介、在野火发起的项目、申请、页脚。仅有已发布项目的发起人生成页面。**不放照片。**

### 6.4 申请表

见第 7 节。

### 6.5 参与须知

见第 8 节。

## 7. 申请表

### 7.1 字段

| 顺序 | 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | 怎么称呼你 | 单行文本 | 是 | |
| 2 | 联系方式 | 单行文本 | 是 | 提示：微信号或邮箱 |
| 3 | 你现在的状态 | 单选 | 是 | 在校学生；已经工作，想转行；其他 |
| 4 | 想加入哪个项目 | 下拉 | 否 | 默认“还没确定，想先聊聊”（any），后接已发布且开放申请的项目，按项目数据顺序显示；下方始终显示通用申请说明 |
| 5 | 想做的岗位 | 多选 | 否 | 岗位表全部选项，按表顺序；选择项目后不筛选 |
| 6 | 简历 | 文件 | 是 | 只收 PDF、DOC、DOCX；单个文件，界面上限 5MB，实际 5MiB |
| 7 | 每周大概能投入多少时间 | 单行文本 | 是 | 提示：没有硬性要求，如实写就行 |
| 8 | 你做过的东西 | 多行文本 | 否 | |
| 9 | 为什么想来 | 多行文本 | 否 | |
| 10 | 同意勾选框 | 勾选 | 是 | 文字见下 |

勾选框的文字（不要改动）：

> 我已阅读并同意参与须知。我知道参与没有工资，项目成果归项目发起人。

其中"参与须知"链接到 `/terms`，新标签页打开，避免丢失已填内容。勾选框**默认不勾选**，不勾选不能提交。

### 7.2 行为

- 关闭模式：顶部“申请暂未开放。”；申请页说明“申请暂未开放，表格暂时不能提交。”；按钮“申请暂未开放”且表单禁用；接口读请求体前返回 503 和“申请暂未开放。”。关闭模式不添加 robots noindex 或 X-Robots-Tag。

- `/apply?project={slug}` 的项目若在下拉中就预选，否则保持 any。后端按同一数据仅接受 any 或已发布且开放的项目；其他项目返回 400：“这个项目暂未开放申请，请重新选择。”。岗位仅接受岗位表 id，无效返回 400：“请选择有效的岗位。”。
- 前端校验和后端校验都要做。后端必须重新校验必填项、文件类型和文件大小，不能只信前端。
- 提交中禁用按钮，防止重复提交。
- 成功：原页面隐藏表单，显示“收到了”、成功文案和“回到首页”链接，不使用 modal。文案来自 `src/data/site.json`：“你的申请已经收到。我们会尽快查看，并通过你留下的联系方式与你联系。”无 JS 提交成功也显示同一文案。
- 失败：在表单上方给出明确提示，保留已填内容（文件需要重新选择时要说明）。提示文案用："提交没有成功，请稍后再试。"
- 防垃圾提交：加一个对人不可见的蜜罐字段，加基本的频率限制。当前不使用第三方验证码。

### 7.3 后端接口

`POST /api/apply`，`multipart/form-data`。校验通过后发一封邮件到 `APPLY_TO_EMAIL`，简历作为附件。

邮件标题：`【野火申请】{称呼} · {实际项目名，或还没确定，想先聊聊}`。正文“想加入哪个项目”写实际选择，“想做的岗位”按岗位 id 查名称；收件人固定，不按项目分派。

邮件正文按表单顺序列出全部字段，末尾必须有这三行，它们是日后的凭证：

```
已勾选同意参与须知：是
参与须知最后更新：{TERMS_VERSION}
提交时间（北京时间）：{北京时间，精确到秒}（UTC {同一时刻的 UTC 时间}）
```

- 邮件发送失败要返回错误，不能向申请人显示成功。
- 服务器不长期保存申请内容和简历。发送完成后不留副本；日志里不得记录申请人的姓名、联系方式和简历内容。
- 不给申请人发自动回复（联系方式可能是微信号）。

## 8. 参与须知

- 正文来自 `src/data/terms/current.json`，当前共十条；`TermsContent` 组件负责渲染。
- 页面顶部只显示“最后更新：YYYY-MM-DD”，不另外显示生效日期或版本编号。日期在 JSON 的 `version` 中维护，同时作为接口同意校验标识，与 Worker 的 `TERMS_VERSION` 一致；申请邮件记录须知最后更新日期和实际提交时间。
- 每次修改须知：旧版原样归档并公开可访问；操作步骤只见 [CONTRIBUTING](../CONTRIBUTING.md#参与须知更新)。

## 9. 视觉规范

观感：深色底，宋体大标题，橙色点缀，克制，像一家项目工作室的官网。直角，细线，没有圆角、阴影和渐变，没有装饰图形，没有表情符号。

颜色：

| 用途 | 值 |
| --- | --- |
| 深色底 | `#0F100D` |
| 深色面板 | `#181A15` |
| 深色上的细线 | `#2B2E26` |
| 深色上的强线（按钮描边、输入框） | `#5C5F54` |
| 深色上的主文字 | `#F3F0E7` |
| 深色上的次文字 | `#D8D4C8` |
| 深色上的辅助文字 | `#A6A396` |
| 强调色 | `#FF6A2B`（上面的文字用 `#0F100D`） |
| 浅色底（有何不同、申请两个区块） | `#F3F0E7` |
| 浅色上的主文字 | `#0F100D` |
| 浅色上的次文字 | `#43453C` |
| 浅色上的细线 | `#C9C5B8` |
| 浅色上的强调小字 | `#A8390C` |

排版：

- 区块小标：13 像素，字间距 0.24em，强调色。
- 大标题（h1）：`clamp(38px, 6.4vw, 88px)`，行高 1.18，最粗字重。
- 区块标题（h2）：`clamp(28px, 3.4vw, 44px)`，行高 1.3。
- 正文 16 到 17 像素，行高 1.75。
- 内容最大宽度 1200 像素；区块左右内边距 `clamp(20px, 6vw, 96px)`，上下 `clamp(64px, 8vw, 120px)`。

持续保持的视觉要求：

- 手机标题保持自然断行，避免将“会。”等孤字单独留在第三行。
- 把这些颜色和尺寸整理成 CSS 变量，统一使用公共样式和组件。

## 10. 验收标准

- [ ] 五类页面都能访问，文字与已确认的页面内容和数据一致。
- [ ] 关闭申请后把项目的 `published` 改成 false，首页卡片数、"共 N 个"、发起人页的项目列表同时变化，申请只列仍已发布且开放的项目及 any，版面不坏。
- [ ] 只有一个项目时、有十个项目时，项目区都显示正常。
- [ ] 仓库代码无 Google 或站外资源请求、无统计加载脚本；边缘统计走 `/wd7e`。仅成功提交一次 apply_success，含 event 和 apply_project，无申请人填写的内容。
- [ ] 390 像素宽度下，每一页都没有页面级横向滚动。
- [ ] 关闭 JavaScript，全部内容可读；项目区退化为普通的横向滚动。
- [ ] 所有"申请加入"按钮直接到 `/apply`；开放项目预选该项目，未开放项目进入通用表单。
- [ ] 申请表：必填项为空、文件类型不对、文件超限、未勾选同意，都提交不了，并有中文提示。
- [ ] 只改数据新增发起人、岗位和开放项目，卡片、计数、发起人页、详情、下拉及岗位勾选均出现；后端接受并在邮件写项目名；关闭开关后选项消失且后端拒绝。
- [ ] 提交成功后，固定收件邮箱收到一封邮件：字段齐全，简历在附件里，末尾有“已勾选同意、参与须知最后更新、提交时间（北京时间及 UTC）”三行。
- [ ] 邮件发送失败时，页面显示失败而不是"收到了"。
- [ ] 参与须知页的最后更新日期与邮件里的须知日期一致。
- [ ] `check:content` 能查出占位符；正式开放必需事项解决后构建通过；未准备的可选项目保持不发布。
- [ ] 键盘可以走完整个申请表；表单控件都有关联的文字标签；文字对比度达到 4.5:1。
- [ ] 每页有各自的标题和描述；`lang="zh-CN"`。
